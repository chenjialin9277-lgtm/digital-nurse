# v0.15.3 按住说话音频采集与有效性校验设计

## 背景与问题证据

v0.15.2 的现场测试视频显示，用户连续三次按住说话，每次持续数秒且现场声音清晰，但服务端均返回“您问：我”。因此问题不是按压时间过短或用户操作错误。客户端当前在麦克风启动失败、权限异常或录音流中断时会吞掉错误，仍继续向服务端发送停止监听；同时客户端没有验证本次会话是否真正采集到足量、非静音的 PCM 音频。这会把空白或近似空白的识别请求提交给服务端。

小智当前 WebSocket 协议仍使用 16 kHz、单声道、60 ms Opus 帧，项目的 v1/v2/v3 二进制封包结构与官方协议一致。本次修复不改变服务端协议。

## 目标

1. Android 平板按住说话时稳定采集内置麦克风语音，不被蓝牙自动路由或播放器残留状态干扰。
2. 麦克风无法启动或录音流发生错误时，立即结束本次会话并向界面报告明确错误。
3. 松手时只有在采集到足量且包含有效声音的音频后，才向服务端提交识别。
4. 未检测到有效语音时显示“未检测到语音，请重试”，不得让服务端把空音频识别成“我”。
5. 不保存、缓存或导出用户的原始录音。

## 非目标

- 不修改小智服务端、知识库或语音识别模型。
- 不新增持续录音、自动唤醒或后台录音。
- 不重写整个 Android 原生录音插件，除非后续真机证据证明现有插件仍无法可靠采集。

## 方案

### Android 录音配置

录音继续使用 `record` 的 PCM 流式接口，保持 16 kHz、单声道、16-bit PCM。Android 使用面向语音识别的输入源，并关闭自动蓝牙音频路由，确保未指定外接设备时使用平板内置麦克风。播放器仍在开始录音前完全释放。

不默认启用回声消除和强降噪，因为按住说话期间播放器已停止，这些处理可能进一步压低部分平板的输入音量。自动增益仅在设备支持时启用。

### 录音会话结果

麦克风层为每次按住说话维护独立统计：收到的 PCM 字节数、编码帧数、峰值振幅和包含有效声音的帧数。统计只存在于内存中，松手或异常后立即清除。

启动方法必须在原生录音真正启动后才成功返回；权限拒绝、启动失败和流错误均向上抛出，不再只打印日志。停止方法返回本次录音结果，供会话层决定提交还是取消。

### 有效语音判定

一次会话必须同时满足以下条件才允许提交：

- 至少产生 5 个完整的 60 ms Opus 帧（300 ms），排除启动瞬间和误触；
- 至少 2 帧的 PCM 峰值达到 256，排除全零、近似静音和错误输入源；
- 录音流没有发生未处理异常。

阈值集中在独立、可测试的判定器中，避免散落在界面或网络代码里。判定应偏向允许正常低声说话，同时可靠拦截全零和极短录音。

### 会话与服务器交互

开始时仍按“暂停播放 → 建立音频订阅 → 发送 listen/start → 启动麦克风”的顺序执行。若启动失败，发送中止消息并恢复播放。

松手后先完整停止麦克风并取得录音结果：

- 有效语音：发送 `listen/stop`，让服务端开始识别；
- 无效语音或流异常：发送 `abort`，不发送会触发识别的 `listen/stop`，恢复播放并把失败原因传给控制器。

控制器收到“未检测到有效语音”后返回空闲状态，保留连接，不进入系统错误页；麦克风权限或硬件启动失败则显示可操作的错误提示。

## 错误处理与隐私

- 权限拒绝：提示用户在系统设置中允许麦克风权限。
- 麦克风启动失败：提示“无法启动麦克风，请检查设备权限或重启应用”。
- 未检测到语音：提示“未检测到语音，请重试”。
- 录音流中断：取消本次识别并提示重试。
- 日志只记录帧数、字节数和振幅统计，不写入 PCM、Opus 内容或用户话语。

## 测试策略

1. 判定器单元测试：正常语音、低声语音、全零静音、极短输入和流错误。
2. 录音会话测试：有效语音发送 stop；无效语音发送 abort 且不发送 stop；启动失败能被控制器感知。
3. 控制器测试：未检测到语音时回到空闲并显示重试提示，不展示错误识别文本。
4. 编码回归测试：PCM 到 60 ms Opus 的帧长和采样数量保持不变。
5. 完整静态分析和全量 Flutter 测试。
6. 构建 v0.15.3 APK，核验包名、版本号、签名、ABI 和 SHA-256；支持从 v0.15.2 直接覆盖安装。

## 验收标准

- 在目标 Android 平板连续进行至少五次、每次两秒以上的不同中文提问，界面不再固定显示“我”。
- 正常语音能显示对应的完整或合理近似识别文本。
- 静音长按和短促误触均不提交识别，界面提示重试。
- 覆盖安装后原有科室配置、激活信息、宣教内容和使用记录保持不变。
- 应用不产生用户录音文件。
